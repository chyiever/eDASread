## 3. Tab1 标注与撤销设计

### 3.1 坐标、数据与绘图对象

- 显示横坐标使用相对当前文件/拼接数据首样本的秒数。
- 纵坐标使用实际通道号。普通文件与数组列索引一致；NPZ 使用 `channel_start + column_index * channel_step` 映射。
- 标记保存为 `dict[int, float]`，键为通道号，值为相对秒数。
- 红线是独立的 `PlotCurveItem`，不依附 Wiggle 波形包络和增益缓存；因此更改增益、翻转、滤波、点段或重建波形不会误删标记。
- 红线仅覆盖其通道附近的短竖直范围，使用红色和高绘制层级，避免变成贯穿全部通道的线。
- 时间值限制在首样本 0 秒与末个有效样本 `(frame_count - 1) / fs` 之间。

### 3.2 原生鼠标事件

`SpaceTimeView.eventFilter()` 在绘图区 viewport 拦截 Ctrl+左键事件，将像素坐标映射到 ViewBox 数据坐标，再吸附至实际存在的通道。

拖动从 `(ch0, t0)` 到 `(ch1, t1)` 时，对中间实际通道按线性路径求时间：

```text
t(ch) = t0 + (ch - ch0) / (ch1 - ch0) * (t1 - t0)
```

同通道拖动采用最新鼠标位置。按实际拖动方向依次更新通道，保证反向拖动的“最近标记”顺序正确。释放事件也参与最后一段补道。

补充测试发现，鼠标短暂离开绘图区会提前结束标注；现已修复：只要 Ctrl 与左键仍保持，绘图区外的移动事件被消费，返回后从最后一个有效点继续，避免漏标或误交给矩形缩放。

### 3.3 Esc 的最近顺序

创建或修改一个通道标记时，先移除该键，再插入最新值，利用字典插入顺序记录最近修改顺序。Esc 使用 `popitem()` 删除末项。

- 一次 Esc 删除一个通道的当前标记；不恢复该通道更早的旧时间。
- 长按 Esc 处理系统产生的自动重复 KeyPress，每个重复事件再删除一项；空集合时不报错。
- 不需要阻塞等待或单独循环计时器。
- 打开弹出设置面板/对话框、或正在输入框编辑时，Esc 优先交给原控件，避免误删标记。
- NPZ 按剩余标记的当前顺序保存，读取后可继续编辑和撤销。

### 3.4 文件组隔离

以源文件路径元组区分当前会话的文件组。切换文件组时切换对应的标记集合；同组重新滤波、重复绘图与图形模式切换保留标记。颜色图模式隐藏红线，切回 Wiggle 后恢复。跨软件重启保留到时须导出 NPZ。

## 4. 间隔为 1 却每 5 道绘制一条的原因与修复

旧逻辑除了用户输入的步长，还设定 `MAX_WIGGLE_TRACES = 150`。当选择 750 道时，内部额外计算 `ceil(750/150) = 5`，即使用户设定 1，也会再次按 5 抽稀。

本次删除隐式 150 道上限：

- 地震道模式、步长 1：绘制全部选中且实际存在的通道。
- 地震道模式、步长 2：每两列绘制一列。
- NPZ 通道间隔为 3 时，步长 1 仍绘制每一列，对应原通道号每次增加 3。
- 像素点模式仍根据用户指定像素间距选道，这是明确选择的另一种显示方式。

性能方面，Wiggle item 直接加入已有 ViewBox，不通过会在每次插入时重复处理已有曲线的 PlotItem 管理路径；波形包络缓存和增益就地更新继续保留。时间维的显示包络降采样也继续保留，不改变导出数据。

750 道 × 96 帧测试确认步长 1 有 750 条波形、步长 2 有 375 条。本环境单次完整准备/绘制检查约 2.3 秒，仅作为小型合成数据的观察值，不代表所有大文件或真实显示硬件性能。大量通道显示会占用更多资源；需要减少绘制量时由用户显式设置步长，不再暗中改变设置。

## 5. 导出与 NPZ 约定

### 5.1 后台导出快照

主线程在点击“导出视图”时构造不可变 `ViewExportRequest`，记录当前元信息、源文件、处理后矩阵引用、时间/列边界、步长、格式和到时快照。后台 `export_view()` 不访问 Qt 控件，避免任务期间切换文件或缩放导致范围混用。

### 5.2 原始整数与处理后数据

| 格式 | 未选择“处理后” | 选择“处理后” |
| --- | --- | --- |
| BIN | 原始 int32 | 当前处理后 rad 数据换算为 int32 |
| TXT | 原始整数转换为 rad 文本 | 当前处理后 rad 文本 |
| NPZ | 原始 int32 + 头 + 到时 | 同左；该选项在 NPZ 模式禁用，后台也强制使用原始整数 |

多文件原始导出逐个读取源文件，按拼接后的全局帧索引计算抽取相位，不在每个文件重新起算。此处同时修复了旧导出在多文件情况下未勾选处理后数据却仍使用处理后矩阵的问题。

### 5.3 时间与空间抽取

设裁剪起始帧为 `f0`，时间步长为 `dt`，起始列为 `c0`，空间步长为 `dc`：

```text
输出采样率 = 输入采样率 / dt
输出首样本时间 = 输入文件首样本时间 + f0 / 输入采样率
输出起始通道号 = 输入 channel_start + c0 * 输入 channel_step
输出通道间隔 = 输入 channel_step * dc
输出到时秒数 = 输入到时秒数 - f0 / 输入采样率
```

两种降采样均为直接按步长抽取，不平均、不作抗混叠滤波，以保持 NPZ 原始整数。只导出本次实际保留的通道，以及输出首、末个保存样本时间内的标记。到时保留小数精度，不强制对齐到新采样网格。

BIN/TXT 不携带通道身份和到时头信息；需要重新恢复这些信息时使用 NPZ。BIN 文件名支持小数采样率，避免将如 1000/3 Hz 四舍五入成整数。所有格式均禁止覆盖本次读取的源文件。

### 5.4 NPZ 结构

NPZ 内含：

1. `data`：非空二维 int32，形状为 frames × channels。
2. `header`：Unicode 字符串标量，内容为 JSON；采用 `allow_pickle=False` 读取。

主要字段如下，完整说明见配套格式文档：

| 字段 | 含义 |
| --- | --- |
| data_type / format_version | 必须为 eDAS / 整数 1 |
| dtype / raw_unfiltered | 必须为 int32 / true |
| channel_count / frame_count | 严格整数，必须与矩阵形状一致 |
| sample_rate_hz | 导出后的正采样率 |
| start_time | 本文件首样本的 ISO 采集时间，未知时 null |
| acquisition_start_time | 最初源数据的采集开始时间，重复裁剪保留 |
| channel_start / channel_step | 第一列的原始通道号、相邻保存列的通道号间隔 |
| channel_numbers | 每列实际通道号列表 |
| arrivals | 通道号与相对首样本秒数，例如 `{"channel":24,"time_s":0.125}` |
| arrival_time_reference | seconds_from_first_sample |
| time_downsample / space_downsample | 本次抽取步长 |
| source_files | 本次直接使用的源文件列表 |

严格区分 JSON 布尔值与整数，不将 true 当版本 1，不将浮点帧数当整数，不将 false 当通道 0。错误标签、缺字段、对象数组、无效采样率、错误形状/映射、重复通道到时或越界到时均拒绝。

### 5.5 NPZ 读取后的通道身份

`FileMetadata` 提供 `channel_index()` 和 `channel_slice()`。所有页面将显示/输入用的实际通道号映射到矩阵列，避免将裁剪起点误当成 0。

例如头信息 `channel_start=20, channel_step=2, channel_count=3`，数据三列对应 20、22、24；绘图、波形选择和标记继续使用这些通道，输入 21 会报错。距离轴按原通道身份换算，f-k 计算将原始道间距乘以保存的通道步长。
