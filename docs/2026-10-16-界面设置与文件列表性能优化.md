# 界面设置与文件列表性能优化

开发与验证日期：2026-10-16。

## 需求与完成结果

1. 标题栏右上角新增“设置”窗口，界面文字默认 18px，可设置 12～28px，立即应用并持久化。
2. 左侧新增“刷新”按钮和 F5 快捷键，重新扫描当前目录，更新文件总数、新增和删除项；尽量保留当前页及有效选择。
3. 扫描与排序均移到后台，支持上万文件目录，主界面不执行逐文件属性读取或完整目录扫描；每页只创建 100 个列表条目。

## 设置与大字号布局

- `scripts/ui/settings_dialog.py`：提供字号、应用、确定、取消、恢复默认。取消只丢弃未应用值；恢复默认后需应用/确定。
- `scripts/core/settings.py`：`appearance/font_size_px` 保存到现有 eDASread INI 存储；缺失或无法解析时默认 18，超范围时夹取至 12～28。
- `scripts/ui/theme.py`：参数、按钮、文件列表、页签、图表坐标和色条使用指定像素字号；标题为至少 24px，保持更明显的层级。输入框按原始宽度缩放，反复调整不会累乘尺寸。
- 应用字号时保留坐标标签、单位、前缀与原有标签样式，避免更新字号导致轴名消失。
- `scripts/ui/control_scroll.py`：五页顶部参数区使用横向滚动容器；保持紧凑行数，窄窗口或大字号下可滚动访问右侧控件。逐层更新布局最小尺寸，防止标签与输入框重叠。
- 默认 18px，1280×800 和 1500×900 测试中，Tab1 Wiggle 参数内容高度均为 154 逻辑像素；需要横向滚动时额外显示滚动条。

## 原卡顿原因与后台快照

原实现由 `MainWindow.load_directory` 在主界面线程调用 `Path.iterdir/is_file`；名称列表排序后还会在界面线程再次排序。按修改时间排序对每个文件执行 `Path.stat`，文件数多、机械盘或网络盘时阻塞 Qt 事件循环。批量压缩确认前同样存在一次同步目录扫描。

当前实现：

- `scripts/io/directory_scan.py` 使用 `os.scandir`，先按扩展名筛选，再确认是文件；按名称排序不读取修改时间，按时间排序在后台读取属性。
- 扫描只建立文件路径快照，不打开所有 BIN/BZ/NPZ 头和样本；选择数据文件后才按原流程读取数据。
- 使用 `FunctionWorker` 执行扫描与排序；完成后主线程仅接收路径列表、更新总数和当前 100 项。列表使用统一条目尺寸和一次性 addItems。
- 每个窗口至多有一个扫描任务；新请求取消旧任务，只保留一个最新待处理请求，避免重复刷新排队。
- `threading.Event` 在目录遍历及排序前后检查取消状态；请求带代次、目录和排序模式，过期结果/错误不会覆盖当前列表。
- 输入目录仍有 400ms 防抖；刷新/F5 立即发出扫描请求。切换目录时使旧数据加载代次失效，防止已排队的旧波形覆盖新请求。
- 刷新同目录尽量恢复有效选择，并抑制重建列表过程的选择信号，避免无意义地重新加载数据。
- 批量压缩确认计数使用已完成扫描的文件快照；等待扫描结束后再操作，不在界面线程重新扫描。压缩本身仍在后台执行。
- 空目录、无效路径、扫描期间删除项及切换目录均有处理；不递归子目录。窗口关闭时取消扫描并丢弃待处理请求。

## 实际使用边界

扫描速度仍取决于磁盘、网络与目录变化频率。取消为协作式，正在执行的单个系统文件访问要返回后才能继续取消；主界面不等待它。文件列表是扫描时的快照，不是实时目录监控；需要获取新增文件时点击刷新。大数据文件的实际加载和计算沿用既有后台处理机制，浏览性能测试不代表整个数据组的计算耗时。

截图及 GUI 测试使用 Qt 离屏绘制；未重新打包 exe，旧 exe 需要重新构建才能包含本次功能。
